# chookjibupUser_FE 구현 현황

- 저장 일시: 2026-07-31
- 저장 목적: `chookjibupUser_BE`(`FEATURE_SPEC.md`)의 5개 API에 맞춰 화면 디자인이 나오기 전 기능 우선으로 구현한 내용을 정리하고, 다음에 이어서 할 작업을 남긴다.
- 문서 상태: 화면 디자인(Figma) 확정 전 임시 스타일로 구현된 상태. 디자인이 나오면 스타일은 전면 교체될 예정이다.
- 관련 문서: `chookjibupUser_BE/FEATURE_SPEC.md`(API 계약), `chookjibupUser_BE/README.md`(백엔드 구조)

## 1. 무엇을 구현했나

`chookjibupUser_BE`가 제공하는 5개 API를 전부 프론트에 연결했다.

| API                                       | 화면                                            |
| ----------------------------------------- | ----------------------------------------------- |
| `POST /api/auth/kakao/login`              | `/login` → 카카오 인가 → `/auth/kakao/callback` |
| `GET /api/festivals`                      | `/`(축제 목록, 페이지네이션)                    |
| `GET /api/festivals/{festivalId}`         | `/festivals/[festivalId]`(축제 상세)            |
| `POST /api/wishlists/{festivalId}/toggle` | 목록·상세 화면의 하트 버튼                      |
| `GET /api/wishlists/me`                   | `/wishlist`(내 찜 목록)                         |

## 2. 파일 구조와 각 파일의 역할

```
src/
├── app/
│   ├── layout.tsx                     # 전역 레이아웃 + Header + Providers(TanStack Query)
│   ├── providers.tsx                  # QueryClientProvider
│   ├── page.tsx                       # 축제 목록 페이지 (FestivalListPanel 렌더)
│   ├── login/page.tsx                 # 카카오 로그인 버튼
│   ├── auth/kakao/callback/page.tsx   # 카카오 인가 코드 수신 → 로그인 API 호출 → 세션 저장
│   ├── festivals/[festivalId]/page.tsx # 축제 상세 페이지 (FestivalDetailPanel 렌더)
│   └── wishlist/page.tsx              # 내 찜 목록 (비로그인 시 로그인 유도)
├── components/layout/Header.tsx       # 로고 + 찜 링크 + 로그인/로그아웃
├── features/
│   ├── auth/
│   │   ├── api.ts                     # kakaoLogin()
│   │   ├── kakao.ts                   # 카카오 인가 URL 생성, redirect_uri 상수
│   │   └── types.ts                   # KakaoLoginRequest, UserLoginResponse
│   ├── festivals/
│   │   ├── api.ts                     # getFestivals(), getFestivalDetail()
│   │   ├── types.ts                   # UserFestivalResponse 등 응답 타입 전체
│   │   ├── FestivalListPanel.tsx      # 목록 + 페이지네이션 + 찜 하트
│   │   └── FestivalDetailPanel.tsx    # 상세 + 부스/혼잡도 + 로드맵 렌더링
│   └── wishlist/
│       ├── api.ts                     # toggleWishlist(), getMyWishlist()
│       ├── types.ts
│       └── WishlistPanel.tsx
├── lib/api/
│   ├── userApiClient.ts               # axios 인스턴스, JWT 헤더 주입, 401 시 세션 클리어
│   ├── types.ts                       # ApiResponse<T>, ApiErrorBody (백엔드 공통 응답 규격)
```

`next.config.ts`의 `rewrites()`가 `/api/auth`, `/api/festivals`, `/api/wishlists`를 `BACKEND_ORIGIN`(기본 `http://localhost:8080`)으로 프록시한다.

## 3. 인증 흐름

1. `/login`에서 "카카오로 로그인" 클릭 → `getKakaoAuthorizeUrl()`이 만든 카카오 인가 URL로 이동
2. 카카오가 `NEXT_PUBLIC_KAKAO_REDIRECT_URI`로 `code` 쿼리파라미터를 붙여 리다이렉트
3. `/auth/kakao/callback`이 `code`를 읽어 `POST /api/auth/kakao/login` 호출
4. 성공하면 `useUserAuthStore.setSession()`으로 accessToken을 zustand persist(localStorage)에 저장하고 `/`로 이동
5. 이후 모든 요청은 `userApiClient`의 request interceptor가 `Authorization: Bearer {accessToken}`을 자동으로 붙임
6. 401 응답을 받으면 response interceptor가 세션을 자동으로 지운다 → 세션을 구독하는 화면들이 자연스럽게 "비로그인" 상태로 바뀐다

## 4. 알려진 제약과 방어 로직

- **오프라인 감지(`fetchStatus: "paused"`) 처리**: TanStack Query는 브라우저가 오프라인이라고 판단하면 재시도를 멈추고 `paused` 상태로 대기하는데, 이 상태는 `isLoading`도 `isError`도 아니라서 놓치기 쉽다. 세 화면(목록/상세/찜) 모두 `query.fetchStatus === "paused"`를 명시적으로 체크해서 "네트워크 연결을 확인해 주세요"를 보여준다.
- **`FESTIVAL_NOT_FOUND`(40402)**: 축제 상세에서 이 에러 코드만 전용 안내("존재하지 않는 축제예요" + 목록으로 돌아가기)로 분기한다. 나머지 에러 코드는 백엔드가 내려주는 `message`를 그대로 보여준다.
- **인증 만료**: 찜 토글이 401 계열(`UNAUTHORIZED`/`AUTH_TOKEN_INVALID`/`AUTH_TOKEN_EXPIRED`)로 실패하면 "로그인이 만료됐어요" 안내를 보여준다(`isAuthExpiredError()`).
- **로드맵 렌더링**: `roadmapType`이 `icon_builder`이고 `canvasWidth`/`canvasHeight`/`icons`가 있으면 아이콘을 좌표 비율(`positionX / canvasWidth * 100%`)로 절대 위치 배치한다. 그 외(`uploaded_image` 또는 아이콘 없음)에는 `baseImageUrl` 원본만 보여준다.

## 5. 아직 안 한 것 / 다음에 할 일

- [ ] **화면 디자인 반영** — 지금은 zinc/heading/body 기본 토큰만 쓴 임시 스타일이다. Figma 디자인이 나오면 컴포넌트 스타일을 전면 교체해야 한다.
- [ ] **환경변수 실제 값 설정** — `.env.example`을 `.env.local`로 복사해서 `NEXT_PUBLIC_KAKAO_CLIENT_ID`(카카오 REST API 키)를 채워야 카카오 로그인 버튼이 실제로 동작한다. 지금은 빈 문자열로 요청이 나간다.
- [ ] **카카오 개발자 콘솔 Redirect URI 등록 확인** — 로컬(`http://localhost:3000/auth/kakao/callback`)과 배포(`https://chookjibup-user-fe.vercel.app/auth/kakao/callback`) 두 개 다 등록됐는지 확인 필요.
- [ ] **실제 백엔드 연동 테스트** — 지금까지는 로컬에 `chookjibupUser_BE`를 띄우지 않은 채로 확인해서, 정상 응답(200) 케이스는 실제로 검증 못 했다. 백엔드를 로컬에서 띄운 뒤(`./gradlew bootRun`, `application-secret.yml` 설정 필요) 전체 플로우를 한 번 더 확인해야 한다.
- [ ] **`status`/`name`/`region` 필터** — `FEATURE_SPEC.md`에 "비회원 조회 시 서버 에러가 발생해서 임시로 제거했다"고 명시돼 있다. 백엔드가 이 필터를 복구하면 프론트에도 검색/필터 UI를 추가해야 한다.
- [ ] **에러 코드 세분화 확대 여부 검토** — 지금은 `FESTIVAL_NOT_FOUND`와 인증 만료 계열만 별도 처리한다. `AUTH_KAKAO_LOGIN_FAILED`, `AUTH_KAKAO_CODE_REQUIRED` 등 나머지 코드도 화면별로 다른 안내가 필요한지는 디자인이 나온 뒤 다시 검토한다.
- [ ] **`globals.css`의 다크모드 미디어 쿼리** — `prefers-color-scheme: dark`가 아직 남아있다. `chookjibupAdmin_FE`에서 같은 이유(라이트 모드 전용 디자인 시스템인데 다크모드 시 배경만 검게 바뀌어 깨짐)로 제거한 적이 있으니, 이 프로젝트도 라이트 모드 전용으로 확정되면 같이 제거를 검토한다.
- [ ] **로그인 화면 카카오 버튼 색상**: `#FEE500`/`#191919`를 하드코딩했다. 디자인 토큰이 정해지면 토큰으로 옮긴다.
